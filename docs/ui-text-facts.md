# Native UI text facts

The ordinary `godot_playtest` tool accepts the explicit option
`ui_text_snapshot: {version: 1}`. Omission preserves the legacy request,
64 KiB `text_observation` and report behavior. Null, unknown versions, extra
keys and the provisional-feedback combination are explicit refusals.

The existing `/playtest` response carries `ui_text_facts` beside each capture
and `ui_text_snapshot` invocation accounting. The host keeps those producer
objects unchanged in `playtest_report.json`, materializes the PNG under
`frames/`, then checks the bytes actually written: SHA256, byte length, PNG
IHDR dimensions and capture frame/scenario association. A missing response,
fact, requested capture, refusal, corrupt/absent PNG, failed write or identity
mismatch is recorded by the separate `ui_text_snapshot_host` receipt. A stale
file cannot substitute for a missing incoming image. Its diagnostics are bounded
(32 fixed-code/index entries plus exact total/omitted counts, at most 8192
bytes in the `json.dumps(indent=2)` host-receipt projection). The recorded
`local_projection_bytes` counts that indented projection, not server-wire bytes.
The ordinary tool return remains `{written, passed}`: the host receipt stays
only in the existing local report and is not a new tool/API response payload.

Host `status: verified` means only that the requested native collection and
written-image identities agree. `rendered_text_status` remains `not_observed`.
A host-incomplete observation does not rewrite gameplay/input/L0 results;
`passed: true` is therefore never a text-audit result. The provider's native
collection state, refusals and first errors remain visible separately.

Version 1 has finite 4096-node/depth-64 collection, 1 MiB per facts object and
32 MiB per invocation's new wire fields, including escaping, metadata, hashes
and refusal envelopes. Final provider `json.dumps` sealing is authoritative.
The host checks those actual encoded sizes/accounting again. There is no new
paging API, provider store, whole-render completeness flag or automatic audit.
An explicit refusal is not a truncated successful corpus. Source identity is
only what the existing checked request/run binding supplies; none is invented.

Native strings are logical/parsed property facts, not all pixels. Rich text,
clipping/reveal, popup/window composition, secret/IME, custom drawing, 3D,
images and glyph effects retain their stated limitations. Native absence is
never evidence of rendered absence.

A separate genuine nonauthor must inspect the whole original same-PNG image
before native candidate locations, including edges/overlays/small text and
bounded magnification as needed. Retain actual visible strings/fragments with
regions and every ambiguous/unexamined text-bearing region, then compare with
native facts and the full actual internal-ID corpus without catalog/type/numeric
exemptions. Confirmed visible tokens are RED. Missing/partial images, unreadable
fragments, absent relevant windows, wrong frame/locale/hash, unresolved conflicts
or required observation refusals remain UNKNOWN. A scoped fallible
REVIEWED_CLEAR is an independent review conclusion, never a field generated by
this tool, an opened-image marker, or a claim over other frames/locales.
