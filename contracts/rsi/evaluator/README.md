# RSI evaluator r2: statement and standalone semantic fake

This is the **STATEMENT** of `rsi.evaluator.contract` r2, not native proof or an accepted evaluator. Only new files under `contracts/rsi/evaluator/` are supplied. The existing application, runner, gateway, scheduler, SDK and stores are unchanged. No benchmark/model/private-gold execution, optimization campaign, adoption, release or deployment is authorized. The fake's `simulation` execution IDs, checker results, accounting and dispatch counters describe its model only.

The subsequent separately registered PROOF attempt must bind the **same** `conformance.run_shared(factory)` scenarios to the genuine host, without changing their meaning, substituting a fake lifecycle or skipping cases for native providers. `test_statement.py` exercises only the fake, SDK graph parsing and the accepted pure data/numeric components. Passing it cannot establish host custody or physical transport enforcement.

## Inventory and exact ownership

`contract.py` defines strict, immutable, unknown-field-refusing Pydantic types. `providers.py` specifies **new** integration seams, not methods already implemented by the accepted host. `fake.py` is standalone apart from Pydantic and standard Python. `conformance.py` has one fixture protocol and identical scenario assertions for both future native and fake bindings. `fixtures/` contains literal SDK-native graph/roles, 12/8 synthetic benchmark package inputs, accepted-codec logical content, ordinary evaluation scenarios and admission vectors. `test_statement.py` supplies meaningful statement checks. No new runtime, scheduler, run/pin ledger, operation database, heartbeat, GO token or optimizer tool registry is introduced.

The public call is `Evaluator.evaluate(EvaluationRequest) -> EvaluationResult | Refusal`. A trusted coordinator constructs the request after resolving explicit host, native-version, benchmark and private programmatic-checker providers; the optimizer does not supply provider objects, filesystem roots, permissions or receipts. `NativeVersionProvider.read` and `BenchmarkProvider` retain accepted interfaces. `AuthorizedHostScope`, `ObservedCellHost`, `PhysicalAdmission` and `TrustedChecker` are explicitly NEW seams. Production implementation must add narrow plumbing around existing host launch/runner/dispatch/gateway and use existing ownership; these protocols alone enforce nothing.

The normative wire schema is `EvaluationRequest.model_json_schema()` / corresponding result/receipt/refusal schemas, exported by the statement test. All fields without a default are required, including explicit nulls. Strict numbers reject booleans/coercion; amounts use nonnegative integer input/output tokens, physical request counts and USD microdollars. Digests carry `sha256:` plus the full 64 lowercase hex characters. Existing SDK/native raw hex identities are losslessly prefixed at the wire boundary, never rehashed into another identity. Existing logical version IDs use the accepted `rsi.pipeline_version.v2` codec; this contract adds no alternative version codec.

A request freezes:

- Evaluation, campaign and round identities; the canonical plan digest over **all** request fields except `plan_identity`.
- One arm (`reference` or `candidate`) or both in fixed reference/candidate order; each selected logical version, native bundle identity, native seal artifact digest, physical generated config, expected real SDK graph version/digest and resolved roles/templates/tools/capabilities digests. These identities are distinct. No SDK run exists in this request.
- Benchmark definition/version, complete public-fixture companion package, complete private resource package, trusted checker code and arm-wide checker-package identity. Each of all 20 cases retains prompt digest, public fixture tree digest, per-case scorer-reference digest, resolved private material digest and trusted max_points. Reference-string identity is not resolved-byte identity. The checker package digest covers checker code and the complete per-case scorer manifest; it is not a per-case ref digest.
- One split, exactly three integer repeats and a precommitted ordered cell list. Order is repetition 1..3, then the benchmark's declared case order filtered to this split, then reference/candidate arm order. Thus paired holdout arms interleave when evaluated together. A one-arm result cannot select a version. No dropped case, extra favorable repeat or reordered retry creates a new measured cell. `max_parallel` is 1 or 2; it bounds owned cell work in addition to platform limits.
- A full runtime profile: app Source/image, exact SDK/wheel, routes/pricing/policy, requested model, ONE concrete provider/model/nonsecret endpoint identity, effort, temperature, output/turn/time limits and transport-admission proof identity. Freeze effective context/template/tool settings separately through policy and bundle identities. No route alias alone, fallback list order collapse, API key, credential header or secret URL is acceptable. The first Source fixture profile names concrete `ark/deepseek-v4-flash`, endpoint label `ark-coding-v3`, explicit high effort, matching the pinned public host examples. This names an existing host provider/model configuration, not a new fictitious provider. It does not attest current live availability, model weights, prices or transport retries; actual runtime admission refuses until those facts are independently established. Offline fixture transport never contacts that endpoint.
- Cell/round/campaign request/token/cost/time envelopes and explicit preexisting host authorization reference. The host authenticates and resolves it; possession of request JSON grants nothing. Holdout requires a genuine host-validated sealed-selection record and its one-use campaign ownership. Numeric ceilings, including the design's $25/$75, are never permission to spend.

Prepare/register through accepted native bundle paths under the normal exclusion, then derive real SDK graph identity. There is no `pin(run)` or `finish_run` API. Native `ObservedCellHost.run_cell` creates one public fixture/project per cell and invokes ordinary launch, registered graph, claim/runner/confirm/output publication and existing settlement/recovery. SDK-created IDs fill `Execution` only after launch. Do not pass optimizer-controlled rows as execution truth. The first diagnostic cell can be inspected independently, but only the complete fixed stage matrix receives complete evaluation status.

## Result, receipts and lifecycle

Preflight malformed/unknown IDs, unavailable/changed providers, bad packages, policy/runtime mismatch, authorization or unsafe resume refuse **before launch or scoreboard mutation**. `Refusal` has `execution=null`, `before_launch=true`, `scoreboard_mutated=false`, `retryable=false`. A malformed wire payload is rejected by strict parsing before `evaluate`; it must not be coerced into a guessed request. Unexpected programming exceptions are not successful refusals.

After any launch, return `EvaluationResult` with every planned cell exactly once in the original order, plus a content-addressed catalog `(receipt_id, full_receipt_digest)`. The receipt ID is a short unique benchmark-row reference, **not an invented SDK run ID**. Per-cell receipts retain the full frozen case/version/package/runtime identity, actual execution or null, complete output/checker identity when scored, every physical attempt and known/unknown totals. Remaining cells after abort are explicit `not_started/ABORTED`, with null execution, no attempts and no invented elapsed time. Their rows stay in the invalid matrix; they are not silently omitted. Preflight refusal does not create these rows.

Only `scored` or genuine settled `task_failure` is valid. Scored receipts contain immutable **complete** findings.md bytes identified by a full snapshot digest and a trusted programmatic checker result. Task failure receives fixed zero via the accepted scorer, with no fabricated checker result, only when its owned execution and accounting are settled and **no external evaluator envelope was exceeded**. Missing required outputs are classified honestly: genuine settled task failure if established; infrastructure/unknown/scorer error otherwise. Envelope exhaustion is invalid even if the task itself has stopped. Unknown execution, missing usage, abandoned future or accounting uncertainty is `unknown`, keeps conservative reservations and stops further dispatch. No quiet/cleanup claim follows from timeout or an SDK completed flag alone.

`complete` requires all planned cells valid. Any unknown yields `unknown`; otherwise any invalid/not-started cell yields `invalid`. None is an adoption decision (`grants_authority=false`). `validate_result` binds every full receipt to the actual request before trusted projection; type validation proves consistency, not that observed facts happened. Native proof must establish the truth from owning SDK/provider/operation/output sources, and retain first failures and later resolution facts.

Stable reasons are MALFORMED_INPUT, UNKNOWN_ID, PROVIDER_UNAVAILABLE/CHANGED, POLICY_REFUSED, INPUT/CHECKER/OUTPUT_MISMATCH, RUNTIME_DRIFT, BUDGET_EXHAUSTED, UNEXPECTED_CHECKPOINT, INFRASTRUCTURE, SCORER_ERROR, UNKNOWN_EXECUTION, UNKNOWN_ACCOUNTING, UNSAFE_RESUME and ABORTED. NONE is valid only for valid scored/task-failure outcomes. Public projection uses these fixed dispositions, never arbitrary exception text.

## Finite useful pilot and enforced custody obligation

A frozen shadow may change only allowed instruction/context ordering under the accepted version policy. Public read-snapshot and output roots are separate from all private checker material. Source/self/repository tools are part of effective authority, not just model-advertised names.

Compile the exact graph, resolved role/provider/schema/code identities, normalized context/source tools, capability grants and context providers, tool nodes, validation/after-deliver hooks, additional tools/templates, implicit self/repo readers and effective output writers **before** registration/launch/claim/advance can produce effects. Enforce exact `(owned run, step, invocation class)` membership and provider/root identity again at real dispatch. Empty or missing grants, unknown run/step/policy and unlisted tools always deny, including the SDK path whose normal empty allowlist is not deny-all. The typed policy inventories invocation classes even when unsupported; unsupported classes receive no grant.

For this slice, dynamic/loop capabilities, external config/run sources, arbitrary file/root expansion, tool nodes, nonempty capabilities, validation/delivery hooks, extra templates/tools, candidate imports, native code, tool provisioning, generic Meta/Runner/config/trace/output readers, bash/HTTP/MCP clients, overlays and unrecognized fields/shapes refuse. A future expanded shape needs an explicit revised finite policy and same-path vectors. Do not mutate a shared ToolLoader to enforce per-cell scope. Keep useful normal public source/context/read/output paths working; a blanket denial is not positive conformance.

The trusted coordinator resolves frozen private resources and checker code. Only trusted coordinator/checker code receives them; the checker consumes full immutable delivered output as data, never imports or executes candidate output. A judge LLM is unnecessary. Do not score the compact/truncated `drive_pipeline` response. Copy only explicit public train projections into a separate root. `TrainProjection` contains exactly schema/evaluation/status, known train prompts, fixed numeric/status cells and `grants_authority=false`. The full benchmark definition contains holdout prompts and cannot be handed to the optimizer. Train prompt digests are checked against frozen train cases. No holdout projection is returned to the optimizer; final holdout owner summary remains trusted-private until the proposal phase is closed.

Private refs/rubrics, raw checker results/errors/traces, arbitrary run IDs and private-reachable directories never enter that public surface. Numeric feedback intentionally reveals scoring information; no semantic noninference, arbitrary-code sandbox, provider-weight immutability, general cybersecurity or proc/FD isolation claim is made. Trusted host/operator code and external model providers are outside this finite in-band untrusted-agent boundary. The fake tests these data semantics, not real custody.

## Physical request admission and accounting obligation

The budget scope is a coordinator-owned object carried through ordinary runner/AgentFactory/AIGateway. At the **actual physical send** boundary, after concrete endpoint and all effective generation parameters are known, `PhysicalAdmission.reserve(PhysicalRequest)` atomically reserves conservative request/token/cost upper bounds across cell, round and campaign, and checks all elapsed deadlines. Price schedule/bounds must be frozen and resolved; unknown/unreliable upper bounds refuse a real campaign before spend. No optimistic cached-token discount. Include initial sends, model retries, fallback, formatter/parameter repairs, transport retries and any future proposal/checker model calls. This statement does not authorize those future model calls.

A guessed LiteLLM retry flag is no transport proof. The supported transport must either admit each actual send or independently prove all underlying automatic retries disabled. `transport_evidence` identifies that evidence; the fake's value explicitly identifies absent real proof. Native Source deterministic transport evidence is still not live model/provider/billing evidence. Existing gateway broad repair/failover handlers must propagate budget denial as nonretryable and stop rather than trying another call.

Every physical receipt retains final effective runtime, cause, conservative reservation and known/positive-no-send/unknown settlement. Runtime drift, hidden effort/output-cap repair or a different serving endpoint invalidates comparison, even if charged. Before/after profile equality alone is insufficient; per-request effective identity and owning ingress/provider checks are mandatory. Changed effective identity must deny before the next send; an already observed mismatched send is retained as invalid evidence, never normalized into the expected profile.

Known measured usage settles under the reserved bound. Positive no-send/nonbillable evidence may release to zero. Disconnect, missing usage, timeout with a live worker or abandoned future retains the full upper bound and blocks new dispatch; unknown is never zero cost or quiescence. Preserve original unknown facts and append resolutions. Unsafe process-loss resume without reliable retained scope refuses; never reconstruct zero spend. Use existing ownership/traces and immutable evaluation artifacts; no separate accounting service or runtime DB. Exact provider invoice totals remain outside the guarantee.

## Accepted data/numeric adapters

`scorer_receipt` maps validated observed receipts to unchanged `core.pipeline_optimization.evaluate_matrix(manifest, receipts, stage=...)`. It uses the arm-wide checker package, trusted max_points and exact Fraction normalization, with fixed task-failure zero. Complete equally repeated arms are necessary for selection; the existing scorer applies inclusive five-point margin, family nonregression and paired eight-case sign-flip rule. The numeric library cannot prove execution/custody/budget truth and does not authorize adoption. Its private receipt return must not be forwarded to the optimizer.

`BenchmarkStore.aggregate()` still requires all 20 cases for every registered arm. A 72-row train-only comparison is incomplete there (48 holdout rows missing), while the accepted numerical stage scorer reports train_complete. Do not redefine the full-document API to obtain a train-only green.

## Native binding (PROOF)

The genuine host binding is production code under `core/`; `native_fixture.py` binds the SAME `conformance.run_shared` scenarios to it (`evidence_kind="native"`), and `test_native.py` adds dedicated native checks. Nothing in the fixture patches a production method; faults change actual host inputs (grants, roots, served registrations, tool providers, provider registry, route table, packages, catalog seals), the deterministic transport fixture's answers, or kill a real second evaluator process.

- `core/rsi_evaluator.py` — the one trusted coordinator. Preflight refuses, with no effects and in this order: authorization and one-use holdout seal; unsafe resume (a durable `started.json` without its live in-process scope); native version identities from the accepted versioning catalog and seals; sealed tool/capability providers; the profile's model provider; benchmark definition, public package, private package, trusted checker code/package; the compiled finite policy; the full served runtime; served physical configs equal to the sealed selections. Cells then run once each in plan order: a public fixture repository pinned at an exact commit, ordinary `start_config_run` of the sealed physical config, the existing non-scheduler driver `core.run_driver.drive_run(auto_approve=False)` on one dedicated thread, SDK settlement read back, the COMPLETE delivered `findings.md` snapshotted immutably and scored by the trusted checker, strict rows through the accepted `BenchmarkStore`. The first invalid/unknown cell stops dispatch; later cells are `not_started/ABORTED`.
- `core/rsi_policy.py` — compiles what a cell would actually execute from the SDK-normalized served graph, served role, manifest, context sources, write/read/host tools, hooks, templates and roots; every other shape is `POLICY_REFUSED`. Host-owned grants must cover every effective tool explicitly; missing or empty grants refuse. `CellPolicy.admits` (claim/advance ingress) and `CellPolicy.dispatch` (each agent tool call, provider identity re-checked) answer for the owned run only.
- `core/rsi_checker.py` — trusted programmatic checker over complete bytes as data; `checker_code` is its served-code identity, `checker_package` binds it to the complete per-case scorer manifest.
- `core/rsi_admission.py` — atomic multi-scope `PhysicalBudget` (the `PhysicalAdmission` seam), per-cell `CellScope`, and `AdmissionTransport`: the gateway hands litellm an OpenAI client whose httpx transport admits EVERY actual HTTP request before it is sent. The openai SDK's own retries (default `max_retries=2` on litellm's OpenAI-compatible path, never disabled by the gateway) therefore remain enabled and each resend is admitted (`transport_retry`). Effective identity is read from the request bytes (URL, model, `max_tokens`, `thinking`, `reasoning_effort`, temperature, unknown keys) against the frozen profile; drift denies before sending. Settlement is read from the wire: completed stream usage is known; an error status settles by the frozen pricing rule `error_status_billable` at status time; a body abandoned before `[DONE]`/EOF, missing usage or a call still held by the transport is unknown, keeps its full bound and closes the budget.
- Narrow seams in existing code: `AIGateway` (scope, admitted client, per-call cause, typed denial re-raised at every handler, and a route gate: litellm's native provider handlers such as `deepseek/` ignore the injected client, so a binding that would send through one is refused before sending), `AgentFactory` (scope, frozen provider/route paths, next cause), `PipelineEngine` (binds the run's scope, never retries or JSON-falls-back a denial, names repair/retry causes), `run_driver` (denial is non-retryable), `start_config_run(evaluation_cell=...)` (read-snapshot isolation of the public fixture at its commit, `_rsi_evaluation` run marker), `run_isolation` (marker/snapshot binding at every resolution) and `AItelierSkillFlow` (ingress refuses an owned run without its live binding or from another thread, takes no checkpoint/resume answers for it; dispatch, tool nodes and hooks other than the SDK's built-in `step_commit` promotion are refused).

Observed host facts the statement fixtures do not express (no vector or criterion was changed for them):

- For a GENERATED config the graph's `x-aitelier` block is inert: the host derives `seed_input.md`, `scheduler_owned: true`, `repo_mode: code` (any `from: repository` source) and here `output_step: null`. The binding therefore publishes the seed file the graph's own seed source names (`task.md`) through `seed_inputs`, isolates the run as a read snapshot (the compiled policy forbids code outputs) and admits only the coordinator's driver thread.
- The literal `identity.json` logical versions and the fixture `checker_code`/`checker_package` are statement constants over simulated providers; native identities come from the real ToolLoader providers and the real checker.
- With a production-like route (profile endpoint plus pay-as-you-go fallback) the gateway retries a burst 429 once and then fails over; a provider 400 is neither failed over nor gateway-retried and the engine re-asks the model in its next attempt. The shared `model_retries` vector binds through the latter; `test_gateway_retry_decorator_sends_are_admitted` covers the former.
